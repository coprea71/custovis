# Plan 1: Fundament

Gemeinsame Grundlage: [../0.md](../0.md). Vorher lesen.

## Ziel dieser Session

Laravel-12-Projekt-Setup, Auth/Guards, Team-/Rechte-Grundgerüst,
Modul-Registry-Mechanismus, Basis-Migrationen, Repo-Grundgerüst.

## Aufgaben

- Laravel-12-Projekt-Setup, `composer.json`, Basis-Konfiguration.
- Fortify (Backend-Logik) + Sanctum installieren/konfigurieren.
- Guards `web` (`users`), `customer` (`customers`), `sanctum` (API) anlegen.
- `teams`/`team_user`-Migrationen + Modelle (eigenes Modell, siehe
  [0.md](0.md) Tech-Stack-Begründung).
- `spatie/laravel-permission` installieren, Basis-Rollen/Permissions-Schema.
- Modul-Registry: `modules`, `module_user`, `module_role`-Migrationen,
  `ModuleServiceProvider` (scannt `module.json`, `enabled`-Flag,
  Zyklen-Erkennung mit Log-Warnung statt Boot-Crash) gemäß
  [0.md](0.md) Abschnitt „Modularität".
- Leere Modul-Platzhalter (`app/Modules/<Name>/` mit `module.json`,
  `Providers/`, `Models/`, `Http/`, `Livewire/`, `Policies/`) für alle in
  [0.md](0.md) genannten Module anlegen (nur Grundgerüst, keine Fachlogik).
- Repo-Grundgerüst: README (inkl. „100% Open Source – keine Paywall"-
  Sektion), CHANGELOG (Keep-a-Changelog/SemVer), LICENSE (AGPLv3),
  `.env.example`.

## Verifikation

- `php artisan migrate --seed` läuft fehlerfrei.
- Login über alle drei Guards (`web`/`customer`/`sanctum`) funktioniert.
- Ein Modul kann über die `modules`-Tabelle aktiviert/deaktiviert werden,
  ohne den Boot zu beeinflussen.
