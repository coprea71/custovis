# Plan 27: E-Mail-Benachrichtigung bei neuen Tickets (je Nutzer schaltbar)

Gemeinsame Grundlage: [0.md](0.md).

## Ziel

Jeder Nutzer kann selbst festlegen, ob er bei neuen Tickets seiner Teams eine E-Mail bekommt.

## Umsetzung

- Spalte `users.notify_new_tickets` (Opt-in, Default `false`), Migration
  `2026_09_26_100000_add_notify_new_tickets_to_users_table`.
- `TicketObserver::created` schickt `NewTicketNotification` an aktive Mitglieder des
  Ticket-Teams mit aktivierter Option; der anlegende Agent wird ausgenommen.
- Versand gequeued (`notifications`-Queue, after commit) über den Standard-Mailer.
  Inhalt nur Betreff, Priorität, Link – keine Kundendaten/Nachrichtentexte.
- Schalter unter „Kontosicherheit → Benachrichtigungen“ (`PUT /account/notifications`,
  FormRequest, Ziel immer der angemeldete Nutzer).
- Tests: `tests/Feature/Account/NewTicketNotificationTest.php`; Hilfe `erste-schritte.md`.
