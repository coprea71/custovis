# Plan 2: Ticket-Kern (Mailbox)

Gemeinsame Grundlage: [../0.md](../0.md). Voraussetzung: [../archiv/1.md](../archiv/1.md) fertig.

## Ziel dieser Session

Ticket-Basisdatenmodell, Mailbox-Verwaltung + IMAP-Fetch, Agenten-Livewire-UI
(Threads, interne Notizen), Collision Detection. Dies ist der Referenzkanal,
auf dem die externe API ([../3.md](../3.md)) und WhatsApp ([../4.md](../4.md))
aufbauen.

## Aufgaben

- Migrationen/Modelle: `tickets` (inkl. `source`-Diskriminator, vorerst nur
  `mailbox`), `ticket_messages`, `ticket_attachments`.
- Mailbox-Verwaltung: `mailboxes`-Migration/Modell/Admin-UI,
  `webklex/laravel-imap`, pro Mailbox eigener Queue-Job `FetchMailboxJob`
  in Queue `mail-fetch`, IMAP/SMTP-Zugangsdaten verschlüsselt
  (`encrypted`-Cast) pro Mailbox-Datensatz.
- Mail-Versand: `MailSenderService` (Queue `mail-send`), als
  gemeinsame Basis für spätere Kanäle wiederverwendbar (DRY) angelegt.
- Agenten-UI (`/agent`) nach UI-Layoutvorlage aus [../0.md](../0.md): Sidebar,
  Master-Detail-Split (Ticketliste + Ticket-Detail), Antwort-Box mit Tabs
  „Öffentliche Antwort"/„Interne Notiz", Textbausteine, Kunden-/Metadaten-
  Sidebar mit Tags. Tailwind über Vite/PostCSS, Farbpalette aus der Vorlage
  übernehmen (kein CDN).
- Collision Detection via Laravel Reverb (wer schaut/bearbeitet gerade
  dasselbe Ticket).
- `AttachmentService` als gemeinsamer Baustein (wird später von WhatsApp und
  Team-Chat mitgenutzt, DRY).

## Verifikation

- Test-Mailbox liefert eingehende Mail als Ticket im Agenten-Bereich.
- Zwei gleichzeitig geöffnete Sessions auf demselben Ticket zeigen den
  Collision-Detection-Hinweis (Reverb).
- Interne Notiz vs. öffentliche Antwort werden korrekt getrennt gespeichert
  und im Thread unterschieden dargestellt.
