# Plan 23: Modulverwaltung & Modul-Zuschaltung

Gemeinsame Grundlage: [0.md](0.md) Abschnitt „Modularität".

## Ausgangslage

`modules`, `module_user`, `module_role` existieren, werden aber nicht ausgewertet; es
gibt keine Admin-Oberfläche. Features liegen im Core (Entscheidung ab Plan 5).

## Ziel

- Modul-Katalog der bestehenden Feature-Bereiche (Knowledge Base, Team-Chat,
  Außendienst, KI, WhatsApp, ERP, Dashboards/Reporting, ITIL-Change/CMDB) mit
  `module.json`-Registrierung wie bisher.
- `/admin/modules` (Permission `modules.manage`): Modul global aktivieren/deaktivieren;
  optional Zuschaltung auf Rollen und/oder einzelne Nutzer beschränken
  (keine Zuordnung = für alle mit passender Berechtigung).
- Durchsetzung: Middleware `module:<slug>` an den Routen der Bereiche,
  `ModuleAccess::allows($user, $slug)` für Navigation/Blade (`@module`).
- Bestandsschutz: Migration aktiviert beim Update alle Module, damit laufende
  Installationen nichts verlieren.
- Modulzugang ≠ Handlungsberechtigung: Permissions werden zusätzlich geprüft.

## Verifikation

- Deaktiviertes Modul: Navigationseintrag weg, Route liefert 404.
- Modul auf Rolle beschränkt: Nutzer ohne Rolle kommt nicht hinein, mit Rolle schon.
